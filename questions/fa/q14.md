# سوال ۱۴: تنظیم Hyperparameter روی Test Set

**موضوع‌ها:** Test Set، Validation Set، نشت اطلاعات، ارزیابی بی‌طرفانه

## 📝 متن سوال

> تیمی ۵۰ بار Hyperparameter را تغییر داده و هر بار مدل را روی Test Set ارزیابی کرده است، سپس بهترین نتیجه را گزارش می‌کند. مشکل کجاست؟

## 🔢 گزینه‌ها

**گزینه ۱:** گزارش بهترین نتیجه اشکالی ندارد، چون هدف نهایی یافتن بهترین عملکرد ممکن مدل است و Test Set همین کار را می‌کند

**گزینه ۲:** تنظیمات باید روی داده آموزش مقایسه می‌شدند، چون Test Set فقط برای مقایسه معماری‌های مختلف مدل کاربرد دارد

**گزینه ۳:** ۵۰ بار آزمایش برای پیدا کردن تنظیم مناسب کافی نیست و برای گزارش قابل‌اعتماد باید دست‌کم چند صد بار تکرار شود

**گزینه ۴:** با انتخاب بهترین از ۵۰ ارزیابی روی Test، آن مجموعه عملاً در فرایند تنظیم شرکت کرده و عدد گزارش‌شده خوش‌بینانه است

## 💡 توضیح سوال

Test Set فقط وقتی تخمینِ **بی‌طرفانه** از عملکرد روی داده‌ی جدید می‌دهد که **هیچ تصمیمی** بر اساس آن گرفته نشود. اگر ۵۰ پیکربندی را روی آن ارزیابی کنیم و بهترین را برگزینیم، در واقع بر اساس Test Set «انتخاب» کرده‌ایم و آن مجموعه عملاً در فرایند تنظیم (مثل یک Validation Set) شرکت کرده است.

نتیجه: بخشی از نمره‌ی بالا حاصل «شانس و برازش به نویز این مجموعه» است و عدد گزارش‌شده خوش‌بینانه (Optimistic) می‌شود. هرچه تعداد آزمایش‌ها بیشتر باشد، این سوگیری بیشتر می‌شود.

## 🔍 بررسی کامل هر گزینه

### گزینه ۱ — ❌ نادرست

> گزارش بهترین نتیجه اشکالی ندارد، چون هدف نهایی یافتن بهترین عملکرد ممکن مدل است و Test Set همین کار را می‌کند

**نادرست.** هدف Test Set یافتن بهترین عملکرد **ممکن** نیست؛ هدف تخمین صادقانه‌ی عملکرد واقعی است. اگر به‌عنوان ابزار جست‌وجو استفاده شود، دیگر معیار بی‌طرف نیست و عدد گزارش‌شده بیش از عملکرد واقعی نشان می‌دهد.

### گزینه ۲ — ❌ نادرست

> تنظیمات باید روی داده آموزش مقایسه می‌شدند، چون Test Set فقط برای مقایسه معماری‌های مختلف مدل کاربرد دارد

**نادرست.** مقایسه‌ی تنظیمات روی داده‌ی آموزش گمراه‌کننده است (مدل‌های پیچیده‌تر همیشه روی داده‌ی آموزش بهتر به نظر می‌رسند و Overfitting دیده نمی‌شود). و ادعای «Test Set فقط برای مقایسه معماری‌هاست» هم غلط است؛ Test Set برای ارزیابی نهایی است، نه برای انتخاب. انتخاب باید روی **Validation Set** یا Cross-Validation انجام شود.

### گزینه ۳ — ❌ نادرست

> ۵۰ بار آزمایش برای پیدا کردن تنظیم مناسب کافی نیست و برای گزارش قابل‌اعتماد باید دست‌کم چند صد بار تکرار شود

**نادرست.** تعداد آزمایش‌ها مشکل اصلی نیست؛ حتی تکرار بیشتر روی همان Test Set سوگیری خوش‌بینانه را **بیشتر** می‌کند. مشکل نوع استفاده از Test Set است، نه تعداد دفعات آزمایش.

### گزینه ۴ — ✅ صحیح

> با انتخاب بهترین از ۵۰ ارزیابی روی Test، آن مجموعه عملاً در فرایند تنظیم شرکت کرده و عدد گزارش‌شده خوش‌بینانه است

**درست.** بهترین نتیجه‌ی ۵۰ ارزیابی روی Test Set یعنی انتخاب بر پایه‌ی آن مجموعه؛ پس Test Set دیگر «دیده‌نشده» نیست و عدد خوش‌بینانه است. راه درست: تنظیم روی Validation Set (یا Cross-Validation / Nested CV) و ارزیابی **یک‌بار** روی Test Set در پایان.

## ✅ گزینه صحیح

**گزینه ۴**

> با انتخاب بهترین از ۵۰ ارزیابی روی Test، آن مجموعه عملاً در فرایند تنظیم شرکت کرده و عدد گزارش‌شده خوش‌بینانه است

## 🎯 علت درست بودن

هر بار که بر اساس نتیجه‌ی Test Set تصمیم می‌گیریم، اطلاعاتی از آن به مدل/تنظیمات نشت می‌کند. انتخاب بهترین از ۵۰ بار، همین نشت را بزرگ می‌کند و گزارش را خوش‌بینانه می‌سازد.

## 📌 نکته کلیدی

سه‌گانه‌ی Train / Validation / Test را رعایت کنید: تنظیم روی Validation، گزارش نهایی یک‌بار روی Test.
