# Question 20: Label Leakage via the “Account Closing Date” Feature

**Topics:** Target Leakage, Data Leakage, Features Available at Prediction Time

## 📝 Question

> To predict ‘will the customer leave the service?’, one of the features is ‘whether the account closing date is empty or not’, and the model gets 99% accuracy. What has happened?

## 🔢 Options

**Option 1:** The training data was small and the model memorized the samples; with more data, accuracy returns to a reasonable level.

**Option 2:** The model underfit and relies on one simple feature; making the model more complex fixes this.

**Option 3:** This feature takes a value only after the customer has left; it reveals the outcome itself and is not available at real prediction time.

**Option 4:** The model has high capacity and the chosen features explain customer behavior well, so such accuracy is natural.

## 💡 About this question

This is a classic example of **target leakage**. "Whether the account closing date is empty" gets a value only **after** the customer leaves; so the feature is effectively the label (non-empty date = customer left). The model only needs to read this one feature to be almost 100% right.

At real prediction time (before churn) this information does not exist, so the model is useless in practice. The warning sign: accuracy that is “too good to be true.”

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> The training data was small and the model memorized the samples; with more data, accuracy returns to a reasonable level.

**Incorrect.** Memorization (overfitting) is usually accompanied by a sharp drop in test accuracy, whereas here the accuracy is high. More data also does not remove leakage; a leaky feature reveals the label with more data too.

### Option 2 — ❌ Incorrect

> The model underfit and relies on one simple feature; making the model more complex fixes this.

**Incorrect.** Underfitting means **low** accuracy, not 99%. The model is actually doing the job well, but by "cheating" with a leaky feature. Making the model more complex does not fix it.

### Option 3 — ✅ Correct

> This feature takes a value only after the customer has left; it reveals the outcome itself and is not available at real prediction time.

**Correct.** This feature is created after the customer leaves and shows the outcome itself; it is not available at real prediction time. It should be removed, keeping only features that exist before the label event.

### Option 4 — ❌ Incorrect

> The model has high capacity and the chosen features explain customer behavior well, so such accuracy is natural.

**Incorrect.** Very high accuracy on a hard problem like customer churn should be treated with **suspicion**, not accepted as natural. Here the high accuracy does not come from the features' explanatory power but from the label being revealed.

## ✅ Correct answer

**Option 3**

> This feature takes a value only after the customer has left; it reveals the outcome itself and is not available at real prediction time.

## 🎯 Why it is correct

The feature exists only after the outcome occurs; so the model effectively uses the "answer" to answer the "question." That is the reason for 99% accuracy.

## 📌 Key takeaway

For every feature ask: “Is this information available at the moment of real prediction?” If not, it is leakage.
