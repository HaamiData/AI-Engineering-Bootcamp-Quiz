# Question 1: RAG for Daily-Changing Internal Documents

**Topics:** RAG, Fine-Tuning, Prompting, Source Citation

## 📝 Question

> An organization wants to run question answering over its internal documents, which change every day, and the answers must cite their sources. What is the best initial approach?

## 🔢 Options

**Option 1:** Used RAG: at query time, it retrieved the relevant, up-to-date documents and gave them to the model so that it writes the answer based on them, with citations.

**Option 2:** Trained a small model from scratch on the organization's documents so that it fully matches the internal data and does not depend on any external source.

**Option 3:** Relied only on careful prompt writing, without giving the model any documents, and asked it to provide the source names along with its answers.

**Option 4:** Fine-Tuned the model on all documents every night so that the model's knowledge is always up to date; the answers also come from the model's internal knowledge.

## 💡 About this question

This question tests the choice among four common ways of making a language model "knowledgeable": **RAG**, **training a model from scratch**, **prompting only**, and **continuous Fine-Tuning**.

The question states two key requirements:

1. The documents **change every day**, so the system's knowledge must always be fresh.
2. The answers must **cite sources**, so we must be able to show which document each claim came from.

The right approach must satisfy both requirements at the same time.

## 🔍 Detailed review of every option

### Option 1 — ✅ Correct

> Used RAG: at query time, it retrieved the relevant, up-to-date documents and gave them to the model so that it writes the answer based on them, with citations.

**Correct.** This option describes the RAG (Retrieval-Augmented Generation) architecture. At question time, a few relevant chunks of the documents are retrieved and given to the model together with the question, so that it writes the answer based on that text.

- **Freshness:** knowledge is read from the document store *at query time*; when a document changes, it is enough to re-index it and answers are immediately up to date, with no retraining.
- **Citations:** every answer is built from specific chunks, so citing the document and section is natural and verifiable.
- **Side benefits:** fewer hallucinations, the ability to enforce access control on documents, and easy removal of a document from the system.
- **Note:** final quality depends on retrieval quality (chunking, embedding model, re-ranking, etc.).

### Option 2 — ❌ Incorrect

> Trained a small model from scratch on the organization's documents so that it fully matches the internal data and does not depend on any external source.

**Incorrect.** Training a language model from scratch on one organization's documents is neither sensible nor practical:

- A language model needs a huge amount of data and compute to learn language and reasoning; an organization's internal documents are far too small for that.
- Knowledge ends up in the weights, and with daily document changes you would have to retrain every time, so the "up to date" requirement is not met.
- A trained model cannot reliably tell which document an answer came from, so the "cite sources" requirement is not met either.
- "Not depending on any external source" was never one of the question's requirements.

### Option 3 — ❌ Incorrect

> Relied only on careful prompt writing, without giving the model any documents, and asked it to provide the source names along with its answers.

**Incorrect.** If no documents are given to the model, it has no access to the organization's internal documents and every answer comes from general knowledge or its own guesses.

- Asking it to "write the source name" in this situation makes the model produce **fabricated but plausible** sources, which is even more dangerous than having no citations.
- Careful prompting improves behavior and answer format, but it cannot create knowledge the model does not have.

### Option 4 — ❌ Incorrect

> Fine-Tuned the model on all documents every night so that the model's knowledge is always up to date; the answers also come from the model's internal knowledge.

**Incorrect.** Nightly Fine-Tuning has several problems:

- It is costly and complex, and it does not guarantee that the model memorizes document details accurately; Fine-Tuning is better suited to changing style and behavior than to injecting precise, reliable knowledge.
- It can cause the model to forget part of its previous knowledge.
- Answers come from the model's "internal knowledge," so reliable source citation is not possible.
- Removing or correcting one document inside the model's weights is not simple, and at best knowledge is updated with a one-day delay.

## ✅ Correct answer

**Option 1**

> Used RAG: at query time, it retrieved the relevant, up-to-date documents and gave them to the model so that it writes the answer based on them, with citations.

## 🎯 Why it is correct

Both requirements in the question, **daily freshness** and **source citation**, come down to keeping knowledge *outside the model*, in a document store, and handing it to the model at query time. That is exactly what RAG does. The other three options either push knowledge into the model's weights or give the model no knowledge at all; as a result they either go stale or cannot cite sources reliably.

## 📌 Key takeaway

When knowledge is dynamic and citations are required, keep the knowledge in an external store and retrieve it at query time (RAG). Fine-Tuning is for changing behavior and style, not a replacement for a knowledge base.
