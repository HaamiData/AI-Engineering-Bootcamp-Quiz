# Question 3: Safe Design of a Record-Deletion Tool for an Agent

**Topics:** Agent Safety, Least Privilege, Human-in-the-Loop, Irreversible Actions

## 📝 Question

> We have given an Agent a tool for “deleting a record from the database.” Which design is more correct?

## 🔢 Options

**Option 1:** Emphasized in the prompt that it should delete a record only when it is completely sure, and considered this sufficient for safety.

**Option 2:** Gave the Agent full access to the database so that it has enough flexibility to do its job even in unforeseen scenarios.

**Option 3:** Gave only the minimum access required and made human approval mandatory before executing destructive or irreversible operations.

**Option 4:** Enabled the delete tool only during low-traffic night hours so that if an error occurs, fewer users are affected.

## 💡 About this question

This question is about **safe design of tool-using Agents**. An Agent's decisions are made by a language model, and a language model is inherently probabilistic: it can make mistakes, hallucinate, or be tricked by **prompt injection**.

Safety therefore must not depend on "the model behaving correctly"; it must be provided by **controls outside the model**. Two relevant principles:

- **Least Privilege:** the Agent gets access only to what it truly needs, keeping the blast radius small.
- **Human-in-the-Loop:** for destructive or irreversible operations, human approval before execution is mandatory.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> Emphasized in the prompt that it should delete a record only when it is completely sure, and considered this sufficient for safety.

**Incorrect.** An instruction in the prompt is a *request* to the model, not a *security control*. The model may fail to follow it for many reasons (mistakes, hallucination, prompt injection, ambiguous instructions). "Only when completely sure" is also neither enforceable nor verifiable, because a model can be completely sure and still be wrong. A prompt can be a helpful extra layer, but it is not enough for safety.

### Option 2 — ❌ Incorrect

> Gave the Agent full access to the database so that it has enough flexibility to do its job even in unforeseen scenarios.

**Incorrect.** Full access violates the principle of least privilege. A single model error or prompt-injection attack could lead to mass deletion or destruction of all the data. "Flexibility" is not worth an irreversible risk; every capability the Agent needs should be defined explicitly and narrowly.

### Option 3 — ✅ Correct

> Gave only the minimum access required and made human approval mandatory before executing destructive or irreversible operations.

**Correct.** This option respects both principles: minimal access shrinks the blast radius, and human approval for destructive operations prevents a wrong decision from being executed automatically. These controls are enforced outside the model and work even when the model is wrong or tricked. (Complementary layers such as soft delete, backups and audit logging are also useful.)

### Option 4 — ❌ Incorrect

> Enabled the delete tool only during low-traffic night hours so that if an error occurs, fewer users are affected.

**Incorrect.** Restricting the execution hours does not reduce the probability or severity of errors; at most it may reduce the number of users affected at that moment. A record that is deleted is still deleted. Worse, at night nobody is usually awake to respond quickly, and an attacker can operate during those same hours. This is a feeling of safety, not a security control.

## ✅ Correct answer

**Option 3**

> Gave only the minimum access required and made human approval mandatory before executing destructive or irreversible operations.

## 🎯 Why it is correct

The language model cannot be the only safety layer. The principled approach is that even if the model errs or is tricked, the **system** prevents the damage: minimal access plus human approval for destructive or irreversible actions. Option 3 implements exactly that.

## 📌 Key takeaway

Secure an Agent with controls outside the model (permissions, approvals, logging), not by asking nicely in the prompt.
