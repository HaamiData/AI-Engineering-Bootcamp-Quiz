# Question 4: Necessary vs Sufficient Condition in a Deployment Rule

**Topics:** Logic, Necessary vs Sufficient, CI/CD, Denying the Antecedent

## 📝 Question

> The team's rule is: “Any change that fails the automated tests is not deployed.” Change X has passed the tests successfully. Which conclusion from this rule is logically correct?

## 🔢 Options

**Option 1:** X will definitely be deployed, because it did not trigger the obstacle stated in the rule.

**Option 2:** X is definitely bug-free, because no test has rejected it.

**Option 3:** The rule has been violated, because a change that has passed the tests should not be deployed.

**Option 4:** Passing the tests is a necessary condition, not necessarily a sufficient one; from the rule we cannot conclude that X will definitely be deployed.

## 💡 About this question

This question tests a simple but frequent logical argument in software engineering: the difference between a **necessary condition** and a **sufficient condition**.

The rule says: "If the tests fail, then the change is not deployed," i.e. `tests fail ⇒ not deployed`. Its logical equivalent (the contrapositive) is: `deployed ⇒ tests passed`. So passing the tests is **necessary** for deployment.

But from "the tests passed" we cannot conclude that deployment happens (it is not sufficient); other conditions may also be required for deployment, such as code-review approval, release authorization, or a release freeze.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> X will definitely be deployed, because it did not trigger the obstacle stated in the rule.

**Incorrect.** This is the fallacy of *denying the antecedent*: from `A ⇒ B` it concludes `¬A ⇒ ¬B`. The rule only says that failing tests blocks deployment; it never says passing is enough to deploy. Other obstacles (human approval, release schedule, etc.) may exist.

### Option 2 — ❌ Incorrect

> X is definitely bug-free, because no test has rejected it.

**Incorrect.** Not failing the tests does not mean there are no bugs; tests only check the behaviors they were written for. "Absence of evidence" is not "evidence of absence." Moreover, this conclusion does not follow from the given rule at all.

### Option 3 — ❌ Incorrect

> The rule has been violated, because a change that has passed the tests should not be deployed.

**Incorrect.** The rule only forbids deploying changes that failed and says nothing about changes that passed. If X passes and is deployed, the rule is not violated; if X passes and is not deployed, the rule is still not violated. This option turns a necessary condition into a prohibition.

### Option 4 — ✅ Correct

> Passing the tests is a necessary condition, not necessarily a sufficient one; from the rule we cannot conclude that X will definitely be deployed.

**Correct.** Passing the tests is necessary for deployment (since failing blocks it) but not necessarily sufficient. Therefore, from the rule we cannot conclude that X will definitely be deployed. This is the only conclusion that logically follows from the rule.

## ✅ Correct answer

**Option 4**

> Passing the tests is a necessary condition, not necessarily a sufficient one; from the rule we cannot conclude that X will definitely be deployed.

## 🎯 Why it is correct

The rule has the form `fail ⇒ not deployed`, whose contrapositive is `deployed ⇒ passed`: passing is **necessary**. The reverse direction (`passed ⇒ deployed`) does not follow from the rule, so option 4 is the only valid conclusion.

## 📌 Key takeaway

Don't flip an implication: from `A ⇒ B` you cannot conclude `B ⇒ A` or `¬A ⇒ ¬B`.
