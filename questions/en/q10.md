# Question 10: Context Management in a Long Chatbot Conversation

**Topics:** Context Window, System Prompt, History Summarization, Chatbot Design

## 📝 Question

> In a long chatbot conversation, after about 50 messages the model no longer follows the initial system instruction and the history has reached the context limit. What is the best design?

## 🔢 Options

**Option 1:** Stated the system instruction only once in the first message of the conversation and sent the full history without any removal or summarization.

**Option 2:** Sent only the user's last message to the model so that the context stays empty and the model focuses on that single message.

**Option 3:** Kept the system instruction fixed and complete at the start of every request and summarized or pruned old messages to leave room for the important content.

**Option 4:** Lowered the Temperature so that the model is more stable in following the system instruction, and there is no longer any need to manage the history.

## 💡 About this question

A language model has **no persistent memory**; in every request it sees only the text we send, and that text has an upper limit (the context window). In long conversations two problems arise: the history hits the limit, and the original instruction gets diluted among a large amount of text (models tend to attend better to the start and end of the context and less reliably to the middle).

So the **context must be managed**: keep the system instruction fixed and complete, and compress old history.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> Stated the system instruction only once in the first message of the conversation and sent the full history without any removal or summarization.

**Incorrect.** If the history grows without removal or summarization, it will hit the context limit and fail, or older parts (including the original instruction) will be truncated. Stating the instruction only once at the start also means its influence fades as the text grows.

### Option 2 — ❌ Incorrect

> Sent only the user's last message to the model so that the context stays empty and the model focuses on that single message.

**Incorrect.** If only the last message is sent, the model loses the whole conversational background (references like "that one," earlier decisions, user preferences). This approach also drops the system instruction unless it is sent separately.

### Option 3 — ✅ Correct

> Kept the system instruction fixed and complete at the start of every request and summarized or pruned old messages to leave room for the important content.

**Correct.** The system instruction is repeated at the start of every request so it always sits in a strong, complete position, and old messages are summarized or pruned (for example a rolling summary plus the last few messages) to leave room for important information while keeping the conversation coherent.

### Option 4 — ❌ Incorrect

> Lowered the Temperature so that the model is more stable in following the system instruction, and there is no longer any need to manage the history.

**Incorrect.** Temperature controls the randomness of sampling, not the context size or how much attention the model pays to the instruction. Lowering it does not stop the history from reaching the limit, so the need for history management remains.

## ✅ Correct answer

**Option 3**

> Kept the system instruction fixed and complete at the start of every request and summarized or pruned old messages to leave room for the important content.

## 🎯 Why it is correct

The problem has two parts (context overflow and a fading instruction), and only option 3 solves both: a fixed, complete instruction in every request plus history compression.

## 📌 Key takeaway

Treat the context like a limited resource: keep important instructions fixed and summarize or prune the history.
