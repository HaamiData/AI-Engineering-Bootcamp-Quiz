# Question 17: Debugging RAG: Retrieval or Generation?

**Topics:** RAG, Retriever, Chunks, Systematic Debugging

## 📝 Question

> In a RAG system, the answer is wrong, but you are sure the correct document exists in the knowledge base. What is the first debugging step?

## 🔢 Options

**Option 1:** First check whether the retriever returned the correct chunk at all, so that retrieval errors are separated from answer-generation errors.

**Option 2:** Added a sentence like “answer accurately and without mistakes” to the prompt so that the model is more careful in using the document.

**Option 3:** Enlarged the context window so that all chunks in the knowledge base are available to the model at once.

## 💡 About this question

A RAG system has two main parts: **retrieval** and **generation**. When the answer is wrong, the cause could be in either, and fixing one has no effect on the other. So the first step is to **isolate the source of the error**: did the right chunk even reach the model?

## 🔍 Detailed review of every option

### Option 1 — ✅ Correct

> First check whether the retriever returned the correct chunk at all, so that retrieval errors are separated from answer-generation errors.

**Correct.** If the retriever did not return the correct chunk, the model could never have answered correctly and the problem is in retrieval (chunking, embedding, Top-K, filters, query). If retrieval was correct but the answer is wrong, the problem is in generation/prompting. This check is the cheapest diagnosis and clarifies the path to a fix.

### Option 2 — ❌ Incorrect

> Added a sentence like “answer accurately and without mistakes” to the prompt so that the model is more careful in using the document.

**Incorrect.** Adding a generic sentence to the prompt is cheap but speculative. If the retriever did not bring the right document, no instruction can get the model information it does not have. Before changing the prompt, you must know whether the problem is in generation or retrieval.

### Option 3 — ❌ Incorrect

> Enlarged the context window so that all chunks in the knowledge base are available to the model at once.

**Incorrect.** Enlarging the context and giving "all chunks in the knowledge base" is practically impossible and defeats the purpose of RAG. Even if feasible, it raises cost and latency and increases noise (the model loses important information in lots of text). It also doesn't find the cause.

## ✅ Correct answer

**Option 1**

> First check whether the retriever returned the correct chunk at all, so that retrieval errors are separated from answer-generation errors.

## 🎯 Why it is correct

Principled debugging means first isolating the faulty stage. Inspecting the retriever's output is the quickest way to tell whether the error comes from retrieval or generation.

## 📌 Key takeaway

In RAG, evaluate retrieval first (did the right chunk come back?), then generation.
