# Question 2: Decision Threshold and Asymmetric Error Cost

**Topics:** Decision Threshold, Error Cost, Fraud Detection, Precision/Recall

## 📝 Question

> In a fraud detection system, missing a real fraud is 100 times more costly than needlessly reviewing a legitimate transaction. Given this, what should be done with the model's decision threshold?

## 🔢 Options

**Option 1:** There is no need to change the threshold; the asymmetric cost of errors only affects the choice of model architecture and has no effect on the threshold.

**Option 2:** Move the threshold close to 0.99 so that only the transactions the model is extremely confident about are flagged as fraud.

**Option 3:** Lower the threshold below 0.5 so that more frauds are detected, even though false alarms and the manual review workload increase.

**Option 4:** Keep the threshold at 0.5, because this value gives the best balance between the two types of error regardless of the cost structure.

## 💡 About this question

This question tests the relationship between **asymmetric error cost** and the **decision threshold**.

A classifier usually outputs a "fraud probability," and the threshold decides above which probability a transaction is flagged as fraud. The default threshold of 0.5 is optimal only when the two kinds of error cost the same:

- **False negative (FN):** a real fraud that is missed, cost: 100 units
- **False positive (FP):** a legitimate transaction needlessly reviewed, cost: 1 unit

A little math: we should flag a transaction when the expected cost of not flagging exceeds the expected cost of flagging, i.e. `p × 100 > (1 − p) × 1`, which gives `p > 1/101 ≈ 0.01` (assuming the model's probabilities are calibrated). So the optimal threshold is far below 0.5.

## 🔍 Detailed review of every option

### Option 1 — ❌ Incorrect

> There is no need to change the threshold; the asymmetric cost of errors only affects the choice of model architecture and has no effect on the threshold.

**Incorrect.** The cost structure of errors directly affects the decision point. Costs can also be applied during training (for example via class weighting or cost-sensitive learning), but the claim that it "only affects architecture and has no effect on the threshold" is wrong. In practice, tuning the threshold is the simplest and most common way to apply a cost structure.

### Option 2 — ❌ Incorrect

> Move the threshold close to 0.99 so that only the transactions the model is extremely confident about are flagged as fraud.

**Incorrect.** The direction is wrong. A high threshold means the model raises an alarm only when it is extremely sure; many frauds are therefore missed (low recall), so the very error that is 100 times costlier increases. This choice would suit a case where false alarms are much more costly than missed real cases, which is the opposite of this situation.

### Option 3 — ✅ Correct

> Lower the threshold below 0.5 so that more frauds are detected, even though false alarms and the manual review workload increase.

**Correct.** Since missing a fraud is far more expensive, we should be willing to accept more false alarms in order to catch more frauds. Lowering the threshold raises recall, at the price of lower precision and a heavier manual review load; the option itself names this trade-off and accepts it.

### Option 4 — ❌ Incorrect

> Keep the threshold at 0.5, because this value gives the best balance between the two types of error regardless of the cost structure.

**Incorrect.** A threshold of 0.5 gives the "best balance" only when the two errors cost the same (and probabilities are calibrated). The phrase "regardless of the cost structure" is exactly the option's mistake, because the question is precisely about the cost structure, which must be reflected in the decision.

## ✅ Correct answer

**Option 3**

> Lower the threshold below 0.5 so that more frauds are detected, even though false alarms and the manual review workload increase.

## 🎯 Why it is correct

With a 100-to-1 cost ratio, the break-even probability is around 0.01, not 0.5. So the threshold should be moved **below 0.5**. In practice the exact value is chosen using validation data, a cost curve or the precision-recall curve, and the capacity of the review team (usually somewhere above 0.01 and below 0.5).

## 📌 Key takeaway

0.5 is a default, not a law. The threshold should come from the error-cost structure and the business need.
